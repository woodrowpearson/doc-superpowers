# Output Templates

## Audit Report

`audit` writes ONE file, `docs/plans/YYYY-MM-DD-audit-report.md` (`-<short HEAD sha>` appended when that name is taken): this report, then its **Update Tasks** section (next heading). It is `update`'s input (`--report=<path>`), and `update` archives it to `docs/archive/plans/` once applied. Quote no secret in it (SKILL.md *Safety Rules*).

```
## Documentation Freshness Audit — {date}

**Branch:** {current branch} · **HEAD:** {short sha}

### Summary
- Scanned: {N} docs across {N} scopes ({scope names})
- Fresh: {N} | Stale: {N} | Missing coverage: {N} | Untracked: {N}

### P0 Critical
1. {doc path}
   - Doc says: "{exact quote}"
   - Code shows: "{exact quote or description}"
   - Suggested fix: "{action}"

### P1 Stale
...

### P2 Incomplete
...

### P3 Style
...

### CLAUDE.md Status
- [ ] Directory Structure: {current | stale — list discrepancies}
- [ ] Key Files: {current | stale — list discrepancies}
- [ ] Commands: {current | stale — list discrepancies}

### README.md Status
- [ ] Feature list: {current | stale — list discrepancies}
- [ ] Command / API list: {current | stale — list discrepancies}
- [ ] Usage examples: {current | stale — list discrepancies}

### RELEASE-NOTES.md Status
- [ ] {current | N commits unreleased since vX.Y.Z (YYYY-MM-DD)}

### Actions
- Run `/doc-superpowers update --report=<this file>` to apply the Update Tasks below
- Run `doc-tools.sh update-index <doc>` after manual review
- If CLAUDE.md flagged stale above, update it per `references/doc-spec.md` CLAUDE.md update rules (in a doc-superpowers CI workflow, `update` reports the change instead)
- If README.md flagged stale above, update it per `references/doc-spec.md` README.md update rules (in a doc-superpowers CI workflow, `update` reports the change instead)
- If RELEASE-NOTES.md flagged stale above, run `/doc-superpowers release` to draft a new version entry
```

## Update Tasks (second half of the audit report file)

Appended to the same file, after the report above. This is the structured handoff to `update`:

```markdown
## Update Tasks

**Generated by:** /doc-superpowers audit
**Branch:** {current branch}

### Scope
{which scopes were audited}

### Findings Summary
| Priority | Count | Action |
|----------|-------|--------|
| P0 Critical | {N} | Must fix before merge |
| P1 Stale | {N} | Update recommended |
| P2 Incomplete | {N} | Add coverage |
| P3 Style | {N} | Low priority |

### P0 — Critical Updates
- [ ] {doc path}: {description of what needs changing}

### P1 — Stale Updates
- [ ] {doc path}: {description}

### P2 — Missing Coverage
- [ ] {doc path}: {description}

### Execution
Run `/doc-superpowers update --report=<this file>` to apply these tasks.
```

`update` reads a report only when it is named with `--report=<path>` or was written by `audit` earlier in the same session — never the newest `*-audit-report.md` it happens to find (it may be from another branch, or applied already).

## Spec Compliance Report

Used by `spec-verify --mode=post-execute`. See `references/spec-lifecycle-actions.md` for the full procedure.

```markdown
## Spec Compliance Report

**Verdict:** PASS | FAIL

### Summary
- Specs: N total, N implemented, N held short of `Implemented`, N exempt, N constraint refs, N amendments, N stale, N missing
- Deviations: N flagged during execution
- CLAUDE.md: {current | stale — N sections drifted}
- README.md: {current | stale — N sections drifted}

### Details

| Spec | Role | Status | Freshness | Notes |
|------|------|--------|----------|-------|
| SPEC-AUTH-001 | target | Implemented | Current | — |
| SPEC-DATA-001 | target | In Review | Stale | Deviation: uses push instead of polling |
| SPEC-API-006 | constraint | In Review | Current | Read-only reference — not advanced by this work |
| SPEC-UI-041 | amends | Implemented | Stale | Amendment landed in `## Design`, cites this plan |

### Unresolved
- SPEC-DATA-001 section 3.2: implementation diverged, needs human review

### Informational (P3)
Non-blocking. Never contributes to a FAIL verdict.
- Inferred constraints: N spec(s) treated as constraint references by inference — pass `:constraint` to confirm, or fix their `code_refs` if they were meant to be implementation targets
- Unrecognized statuses: N spec(s) at an unrecognized status — automation will never transition these
- Amendments verified: N amendment(s) verified as landed (a no-`--plan` check is listed with its `WARN: amendment citation unverified (no --plan)`, not counted)
- Held at `In Review` (or left at `Approved`): N partially-covered target(s) held by design, remaining scope recorded in Implementation Notes

### Recommendation
[Fix before merging | Accept with noted gaps | Block merge]
```
