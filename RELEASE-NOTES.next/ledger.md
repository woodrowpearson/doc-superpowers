### Added
- **Work ledger (opt-in)**: `doc-tools.sh ledger`, a new verb group of 18 verbs — `show`, `ls`, `find`, `related`, `sweep`, `recheck`, `inflight`, `notices`, `state-watch`, `new`, `assign`, `link`, `note`, `view`, `validate`, `publish`, `finalize`, `init` — that keeps work items as issue files (or hosted GitHub issues), gives each a stable key allocated by compare-and-swap on a counter ref (provisional keys offline; `keys.mode: merge` for fork-and-PR repositories), generates ledger pages and one HTML view from the items, relates work through named contracts, and raises in-flight notices across branches and machines. It is inert without `docs/ledger/config.json` (`{}` is a complete config): every verb but `init` prints `ledger: not enabled (no docs/ledger/config.json)` and exits 0. Exit codes are the claims family (0 ok, 1 findings, 2 could not run, 3 usage). New files: `scripts/ledger/` (a `lib.sh` and twelve modules over jq and awk programs; bash 3.2 + jq ≥ 1.6), the reference adapters `scripts/adapters/ledger-pr-gh.sh` and `ledger-items-gh.sh` (GitHub through `gh`, addressed as `doc-superpowers:<name>`), `references/ledger.md` (the reference) and `references/ledger-index.schema.json` (the index shape).
- **Ledger bootstrap**: `ledger init --report` proposes a registry and assignment decisions from the issues, GitHub issues and hand-written ledger tables a repository already has; `--accept` applies exactly what the owner decided (config, registry, keys in one counter commit, item fields, stubs for open hand-written rows, `docs/ledger/legacy.json`); `--import` turns hosted issues into files once. The skill's `init` action runs it as an opt-in step (12b), with the user's review in between.
- **Ledger hook sets**: `hooks install --ledger` (marked `# ledger-superpowers:begin` … `:end` blocks: pre-commit `ledger validate --staged`, which blocks on any non-zero exit; pre-push, which refuses a provisional key in `cas` mode; post-commit `ledger inflight --push`, in the background, logging to `push.log`) and `hooks install --ledger-claude` (SessionStart in-flight notices, PostToolUse `Write|Edit` state-watch). Both are opt-in, never part of `--all`, refused without `docs/ledger/config.json`, and not recorded in `installed.json`. Hosts that keep hooks in a committed `.claude/settings.json` can register the hook modes `ledger notices --hook` and `ledger state-watch --hook` directly (`references/hooks.md`).
- **`doc-ledger-publish.yml`** (CI, opt-in by name, no AI and no secret): every 30 minutes and by hand, `ledger publish` renders the views from the base and pushes them to the `doc-ledger-views` branch, and with in-flight awareness on prunes stale in-flight refs. It ships the ledger helper set.
- **SKILL.md**: a `ledger` action; with `docs/ledger/config.json`, `spec-inject --phase=plan` pastes the `ledger sweep --plan` table into the plan as `## Related work` and injects a `Ledger notices (chunk N)` task (`ledger notices --gate`) in each chunk.
- **Spec claims × ledger**: each ledger item counts the `diverged` / `unbuilt` spec claims whose tracker names it (`show`, the views, `--format json`).
- **`tools install --helper ledger`** vendors the ledger set (`<dest>/ledger/`, `<dest>/adapters/`); `--helper` now names sets.
- **Tests**: `scripts/test-ledger.sh`, a seventh suite (with a 300-item smoke of the design budgets ×3), and `scripts/bench-ledger.sh 3000`, the full performance check, run by hand. The bash-4 and jq-1.7 static guards now scan `scripts/ledger/` and `scripts/adapters/`. A ledger eval, `spec-inject-ledger`. Seven suites, 10,884 assertions at the end of the arc (test-doc-tools 1434, test-hooks 1417, test-spec-status-model 668, test-doc-pr-release 621, test-merge-driver 600, test-spec-claims 3269, test-ledger 2875), under bash 5.x and `/bin/bash` 3.2.

### Changed
- **Spec-claims V5 with the ledger on**: a tracker that names a ledger item (its path, or a key or alias one item carries) is open or closed by the ledger's status classes, so `Won't Fix`, `Not planned` and `Obsolete` now close a tracker — an `unbuilt`, `diverged` or `gated` claim tracked by such an item becomes a V5 finding. An item whose status no class names is read as before. A ledger that cannot be read is one indeterminate V5 row (`ledger-unavailable`, exit 2). With the ledger off, V5 is byte-identical to 3.2.0.
- **Claims workflows ship the ledger helper set**: `doc-freshness-schedule` and `doc-spec-verify` now vendor `.github/scripts/ledger/` and `.github/scripts/adapters/`, whether or not the ledger is enabled. **After upgrading, a host with either workflow re-runs `hooks install --ci` and commits the two new directories** (`hooks status --ci` warns until then). A file of the host's own under `.github/scripts/ledger/` or `.github/scripts/adapters/` with a shipped file's name is replaced by `install --ci`: keep host adapters elsewhere and name them by path.
- **`DOC_SUPERPOWERS_SKIP=1` covers the ledger legs too**; `DOC_SUPERPOWERS_LEDGER_SKIP=1` skips only them. `DOC_TOOLS_LEDGER_OFFLINE=1` keeps every ledger verb off the network.
- **Docs**: the 3.3.0 audit's update tasks applied across SKILL.md, the references, README, CLAUDE.md and `docs/` (claims surfaces, exit families, counts kept only in CLAUDE.md); `docs/conventions.md` gains a Testing section and records this repo's Scope-matrix exemptions (42797cf); every changed diagram re-rendered.

### Fixed
- **The git tier's integrated pre-push block fails closed**: when it cannot copy git's ref lines for the hook after it, it now refuses the push instead of letting the user's hook read nothing and pass. **Re-run `hooks install --git` after upgrading**: an older integrated block keeps the old behaviour until then, and `hooks status --git` marks it outdated.

### Notes
- **claude.ai/code and the counter ref**: a claude.ai/code session's git proxy refuses (HTTP 403) every push under `refs/doc-superpowers/…`, and deletes under `refs/heads/…`. With the default `keys.counter_ref` (`refs/doc-superpowers/ledger/counters`) a cloud session cannot allocate keys (it gets provisional ones). Hosts used from claude.ai/code set `keys.counter_ref` under `refs/heads/`, e.g. `refs/heads/doc-superpowers/ledger-counters`; `inflight --push` reports the 403 as a permission failure (a `push.log` warning, exit 0).
- **Privacy**: enabling the ledger's in-flight layer (`inflight.enabled`) publishes local branch names to the shared remote under a host pseudonym; set `inflight.host_id` when that matters.
