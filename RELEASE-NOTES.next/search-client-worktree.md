doc-search now searches the MCP client's worktree when a call names none. Before, the default was the worktree the server started in. The Claude desktop app starts a project's MCP servers in its main checkout (`claude --project-config-root <main checkout>`) while the session works in a worktree, so every `search`, `fetch` and `related` without `worktree` read the main checkout's files. The cloud leg's branch-changed filter ran against the wrong tree too. Nothing said so: when both trees were at the base branch the answers matched, and otherwise the session got another tree's text.

### Upgrading
Re-run `hooks install --search` and commit the launcher it writes: `scripts/search/launch.sh` changed, so the committed `.claude/doc-superpowers/search-mcp.sh` reads `outdated` until then. A server started by the old launcher keeps the old default; nothing else changes. A project rule that tells agents to pass `worktree:` on every call can drop that once the new launcher is committed (passing it stays harmless).

### Fixes
- **The client's worktree is the default** (`references/search.md` → *Tools* → `worktree`). For `serve`, the launcher exports its parent process's working directory as `DOC_SEARCH_CLIENT_CWD`, unless it is already set. It reads `/proc/$PPID/cwd` on Linux and falls back to `lsof`. With `exec` in an `sh -c` wrapper, as `.mcp.json` entries usually are, that parent is the MCP client. The server makes the worktree holding that directory the default for every tool and warms its indexes first, when it is one of this repository's worktrees. A directory anywhere else, or none, keeps the launch worktree. A `worktree` argument still wins, and the config is still the launch worktree's, so a branch cut before a project adopted doc-search is searchable too.
- **`status` names the default.** The default worktree is listed first, with a `default worktree: <path> (the client's working directory; the server was launched in <top>)` line, or `(the client's working directory <dir> is not a worktree of this repository)` when it could not be used.

### Other
- MCP roots cannot carry this. Claude Code declares the `roots` capability, but the MCP SDK 2.x marks roots deprecated (SEP-2577), and `list_roots()` raises `NoBackChannelError` inside a tool call. The parent process's cwd is the one signal the client gives a server about where its session works.
- Tests: `test-hooks.sh` (`serve` exports the parent's cwd, not the launcher's; a set value is kept; other verbs leave it unset) and doc-search's pytest suite (`client_worktree`, `resolve_worktree`'s default, the server's default and `status` line).
