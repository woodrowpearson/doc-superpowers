This release stops `hooks install --ci` from writing a personal GitHub URL into a project. A client project installed only `doc-ledger-publish` and still received `.github/scripts/doc-superpowers-steps/prepare-agent.sh`, which that workflow never runs and whose default marketplace URL names the maintainer's GitHub account. The project forbids personal identifiers in its repository, so the file had to be dropped by hand, and the next `install --ci` would have vendored it again. Now `install --ci` vendors only the step scripts the installed workflows run. No shipped file names a URL any more: the AI workflows get their marketplace URL from the installer.

### Upgrading from 3.8.1
Re-run `hooks install --ci` and commit what it writes. One run refreshes every managed workflow and vendors their step scripts together, so nothing breaks.
- **AI workflows** (`doc-audit-update`, `doc-review-pr`, `doc-release`, `doc-spec-verify`, `doc-pr-full-cycle`, `doc-pr-release`) gain an env line, `DOC_SUPERPOWERS_MARKETPLACE_URL: "<url>"`. By default the URL is the plugin's own repository (`.claude-plugin/plugin.json` → `repository`, with `.git`), the same URL the old `prepare-agent.sh` defaulted to. The plugin is fetched from where it always was.
- **`prepare-agent.sh` has no default URL any more.** With `DOC_SUPERPOWERS_MARKETPLACE_URL` unset it fails with `::error::doc-superpowers: DOC_SUPERPOWERS_MARKETPLACE_URL is not set …`. That only happens if the new copy is vendored without re-rendering its workflow (for example, copied in by hand); `install --ci` always writes both. Until the re-run, the 3.8.1 workflows and their 3.8.1 copies keep working as they are.
- **Unused step scripts go.** A 3.8.1 install vendored all eleven step scripts. The re-run removes each one no installed workflow runs when it is byte-identical to the plugin's copy. A copy that differs is kept and reported (`Kept …`). That includes every 3.8.1 `prepare-agent.sh`, since its default-URL line changed. `hooks status --ci` then lists it as `⚠ .github/scripts/doc-superpowers-steps/prepare-agent.sh: no installed workflow runs it — removable`; delete it and commit.
- **The two default shell workflows** change only their comment footers: the freshness PR comment and the scheduled audit issue now end `*Generated by doc-superpowers*` (and `… scheduled audit*`), without the repository link. Existing comments and issues are still found by their marker.

### Fixes
- **Step scripts follow the workflows one by one.** `install --ci` vendors each step script in `.github/scripts/doc-superpowers-steps/` that an installed workflow names outside a comment (a `hashFiles(…)`-guarded reference counts only when another workflow ships it), plus, transitively, each sibling that one of them runs as `"$(dirname "$0")/<name>.sh"` (`prepare-agent.sh` snapshots `commit-changes.sh`). The list is read from the workflow and script files, not kept by hand. `doc-ledger-publish` alone ships `ledger-publish.sh` and no other. `uninstall --ci --workflows=<name>` removes the scripts only that workflow ran (byte-identical only).
- **No shipped file names a personal URL.** The marketplace URL moved from `prepare-agent.sh`'s default into the AI templates' env, rendered at install time. The freshness footers lost their link. A test now fails if any template, step script, helper or vendored tool names the plugin owner's account, or if anything `install --ci` writes names it outside that rendered env line.

### Added
- **`hooks install --ci --marketplace-url <git URL>`**: where the AI workflows fetch the plugin, at its release tag. For a project that keeps personal identifiers out of its files, point it at a mirror you control that carries the release tags. It is recorded in `installed.json` as `.tiers.ci.marketplace_url` (only when given; the default is never recorded), and a plain `install --ci` keeps it. `--marketplace-url=` clears it. The value may contain letters, digits and `. _ ~ : / @ % + = , -`, and must not start with `-`; anything else exits 1 and writes nothing. `status --ci` shows it among the choices; `status --json` shows it as `.tiers.ci.choices.marketplace_url`.
- **`hooks status --ci` reports unused step scripts**: a vendored step script that no installed workflow runs reads `⚠ <path>: no installed workflow runs it — removable`. `status --json` lists it in `.tiers.ci.removable_vendored`, a new key in the `doc-superpowers-hooks-status/1` shape.
- **`doc-tools.sh tools install|uninstall --step <script>`** (repeatable, `.sh` optional): only the named step scripts of `doc-superpowers-steps`, exactly as named, instead of `--helper doc-superpowers-steps`. Combining them, or using `--step` with `--with-helpers`, exits 2. `tools uninstall --step` reports each named script it keeps. `install --ci` uses it, one `--step` per script its workflows run.

### Other
- `scripts/check-self-install.sh` now requires `.github/scripts/doc-superpowers-steps/` to hold exactly the step scripts the installed workflows run, with the scripts those run. It also renders `__MARKETPLACE_URL__`. This repository's own tier drops nine step scripts and keeps `freshness-check.sh` and `claims-check.sh`.
- Tests: `test-hooks.sh` (steps follow the workflows, including a ledger-publish-only install and review/full-cycle installs; the upgrade prune and the `removable` status; no personal URL in anything installed; `--marketplace-url` render, record, keep, clear and refuse), `test-doc-tools.sh` (`tools --step`), and `test-doc-pr-release.sh` (`prepare-agent.sh` without the env; a static scan of every shipped file). Seven suites, 12934 assertions (from 12860: test-doc-tools 1575, test-hooks 2032, test-doc-pr-release 630), under bash 5.x and `/bin/bash` 3.2; doc-search's pytest suite unchanged (768).
